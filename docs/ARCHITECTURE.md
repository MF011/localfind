# Архитектура и решения

Rust core: SQLite, обнаружение файлов, сверка, очередь, поиск и ранжирование.
Tauri 2 + React/TypeScript: локальный интерфейс; IPC принимает идентификаторы
индексированных файлов для операций, а не произвольные shell-команды.
Python worker: отдельный процесс для PDF/Office/OCR. В исходной сборке
требуется Python; автономная упаковка должна быть проверена на Windows.

ADR-001: SQLite FTS5 вместо начального Tantivy. Встроенные trigram для
нормализованных имён/путей и unicode61 для текста проверены экспериментом.
Одна транзакционная БД избегает двойной записи между индексом и метаданными.
Для запросов короче трёх символов нужен ограниченный SQL-поиск.
Не обещается морфология/стемминг; русский и английский проверяются отдельно.

UI не разделяет mutex с долгим обходом. WAL, короткие транзакции и отдельные
соединения допускают поиск при индексации. Состояния очереди сохраняются;
прерванные задачи возвращаются в pending. Незавершённый обход не удаляет записи.
Недоступный корень сохраняет индекс. Сверка обязательна даже при уведомлениях.

Приоритет: Windows THREAD_MODE_BACKGROUND_BEGIN для обхода;
IDLE_PRIORITY_CLASS и background mode для дочерних процессов. Не понижать UI.
На Linux — nice 19 для фоновой работы. Это не гарантия нулевой конкуренции
за память/диск. Каждый worker имеет timeout, лимит вывода и размер входного файла.

Имена индексируются раньше извлечения и OCR. Страницы PDF с достаточным
встроенным текстом не проходят OCR. Эта эвристика может пропустить изображение
с текстом на странице, уже содержащей текстовый слой; ограничение явно указано.
Текстовый preview рендерится React как текст, без HTML/макросов/скриптов.
Нормальные логи не содержат извлечённого текста и запросов.

## Реализованные ограничения процессов и кэша

Windows Job Object ограничивает суммарную память worker и потомков 1,5 ГиБ
и завершает их при закрытии job/отмене. Linux использует RLIMIT_AS и отдельную
process group. Число процессов выбирается автоматически при запуске: минимум из числа CPU и
бюджета доступной RAM (резерв 1 ГиБ, по 1,5 ГиБ на процесс). Между готовыми
заданиями нет искусственных пауз. Пользователь может уменьшить параллелизм.
При запуске сигнатура включает версии PDFium/Pillow/Tesseract и SHA-256 моделей
rus/eng/osd. Изменение настроек OCR инвалидирует связанные результаты сразу;
замена моделей на диске обнаруживается при следующем запуске.
SQLite schema version=1; новая несовместимая версия отвергается.
OS file lock запрещает два одновременных владельца индекса.
Текущие уведомления запускают сверочный обход, а не точечное обновление записи.
