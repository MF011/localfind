# Проверки и измерения — 14 ноября 2026

## Среда

Debian 13 x64, Linux-контейнер, Intel Xeon Platinum 8370C @2.80GHz,
3 vCPU, примерно 9,7 ГиБ RAM, локальная overlay FS. Rust 1.100.0,
Node 24.22.1, Python 3.12.14, SQLite bundled rusqlite 0.32.1,
PDFium через pypdfium2 5.13.0, Pillow 13.0.0, Tesseract 5.5.0.
Это не Windows-машина и не испытание реального диска пользователя.

## Что проверено

- 10 Rust integration tests: кириллица/смешанные имена, короткие подстроки и пути,
  фильтр размера, переименование/удаление, недоступное расположение,
  удаление папки с полнотекстовыми данными, исключения, цикл symlink,
  прерванный обход, восстановление очереди, блокировка второго экземпляра,
  реальные Python extraction/phrase search/cache и изменение файла,
  остановка процесса с очисткой временного файла, отсутствие повторного использования id,
  автодобавление дисков и объединение расположений без потери извлечённого текста.
- 7 Python tests: кодировки, DOCX/PPTX, XLSX с формулой/сохранённым значением,
  текст/скан в одном PDF и OCR страницы, повреждённый/защищённый PDF,
  запрет DTD, изменение сигнатуры после изменения языковой модели.
- 2 Playwright tests в Chromium: честное отсутствие backend в веб-просмотре,
  сохранение темы, фильтры/клавиатура; контракт IPC поиска, просмотра и паузы,
  подсветка и вывод HTML как текста. **IPC-тест использует тестовый двойник.**
- TypeScript/Vite production build; Rust clippy с `-D warnings`.
- `cargo check -p localfind --target x86_64-pc-windows-gnu` с MinGW:
  типизация и компиляция Windows-кода прошли, включая Tauri IPC и Job Object.
  Это не создание/запуск подписанного установщика и не проверка Windows GUI.

## Поиск и индекс

Release benchmark: 100 000 синтетических записей имён/путей, 10 000 коротких
текстовых блоков, по 100 запросов с отбрасыванием первых 10 прогревочных.
Набор имён включает частые слова, редкие коды, пути и двухсимвольный запрос.
Отдельно измеряются поиски `names` и `text`. Поиск возвращает максимум 200 файлов.

| Показатель | Значение |
|---|---:|
| Имена p50 / p95 | 0,79 / 12,76 мс |
| Содержимое p50 / p95 | 83,25 / 149,52 мс |
| Вставка 100 000 записей + 10 000 блоков | 9,04 с |
| Скорость синтетической вставки | 11 064 файлов/с |
| SQLite + WAL + SHM на момент измерения | 141 602 240 байт |
| Время процесса всего | 16,58 с |
| CPU user / system | 12,77 / 2,49 с |
| Peak RSS процесса benchmark | 9 088 КиБ |

Peak RSS не включает файловый кэш ядра, GUI и OCR; это не оценка памяти всего
приложения. Сырые данные: `results/search-benchmark.json`.
Предыдущий прогон оптимизированного поиска дал p95 23,62 мс и 108,35 мс;
разброс подчёркивает зависимость от нагрузки. До оптимизации частых запросов
p95 имён был 629,15 мс. Цель <100 мс достигнута в данном тесте, не гарантирована
для любого набора/накопителя. Морфология и нечёткий поиск не измерялись.

Отдельный реальный filesystem fixture, 10 000 файлов по 128 байт:
- Первичный обход: 1,358 с, 7 365 файлов/с.
- Появление нового файла при работающих watcher/сверке: 2 365,5 мс, одно наблюдение.
Это не p95 инкрементальных обновлений и не Throughput OCR/парсеров.
Уведомления пока запускают полный обход, поэтому большая коллекция обновляется дольше.

## OCR

Сравнение двух локальных движков и сырые результаты — `OCR.md`.
Tesseract распознал 4 небольших синтетических изображения за 5,085 с
(около 47 изображений/мин для этого размера), средний CER 1,30%.
Переносить эту скорость на произвольные PDF/фотографии нельзя.

## Статус этапов

| Этап | Реализовано и проверено | Остаток |
|---|---|---|
| A | Индекс, поиск, настройки и действия подключены; ядро проверено в Linux | Реальные диски/Explorer/длинные пути/приоритеты на Windows |
| B | Извлечение форматов, фразы, ссылки, безопасный текстовый просмотр | Более широкий корпус сложных Office/PDF; ограничения FORMATS.md |
| C | OCR, очередь, кэш, поворот, ограничения и отмена | Фотографии реального качества, runtime-проверка Windows Job Object |
| D | Тесты, измерения, рецепт NSIS и ручной Windows workflow | Автономная упаковка Python/Tesseract, Windows acceptance, полный license audit, подпись |

Не проверены: GUI на Windows, повышение DPI, экранный диктор, права NTFS,
реальные OneDrive placeholders/USB/UNC, жёсткие сбои ОС и повреждение SQLite.
При повреждении базы нет автоматического salvage; требуется сохранение копии
и ручное пересоздание индекса. Проект не обозначен production-ready.
